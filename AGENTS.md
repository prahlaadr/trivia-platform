# AGENTS.md — Trivia Platform

Onboarding for humans and LLM agents working in this repo. (Claude Code also
reads `CLAUDE.md`; this file is the tool-agnostic version and the source of
truth for collaborators.)

## What this is

A trivia hosting platform for live pub-quiz nights, deployed on Vercel at
**trivia.pyaarproject.org** (Vercel project `pyaar-trivia`). It has a generic
quiz engine (upload/parse → present → score) and a bespoke, self-contained
**Out of Pocket (OOP)** quiz module that is the current focus of collaboration.

## Repo geography (what's authoritative)

The repo holds **two separate worlds** — don't confuse them:

- **`web/` — the deployed app.** This is what runs at trivia.pyaarproject.org. Almost all changes happen here. TypeScript/Next.
- **Root Python files — offline tooling, NOT deployed.** `parser.py`, `generate_pptx.py`, `pyproject.toml`, and the `bank/` `data/` `output/` dirs are standalone scripts (batch parsing, PowerPoint export). The live site does **not** import them. There is an intentional name overlap: `parser.py` (offline CLI) vs `web/src/lib/parser.ts` (the one the site actually uses) — **edit the `.ts` one** for site behavior.

When in doubt: if it affects the website, it's under `web/`.

## Stack & commands

- **Runtime:** Bun (not npm). **Framework:** Next.js 16 + React 19 + TypeScript + Tailwind v4.
- All app code lives in `web/`. Run everything from there:
  ```bash
  cd web
  bun install
  bun dev          # http://localhost:3000
  bun run build    # production build — run before pushing
  bunx tsc --noEmit  # typecheck
  ```
- **Deploy:** auto from `main` (production). **Every PR gets its own Vercel preview URL** — use it to review changes live before merging. Never push straight to `main`; open a PR.

## Collaboration workflow

- Branch off `main`: `oop/<short-description>` for OOP work, `platform/<...>` otherwise.
- Open a PR; check the Vercel preview; request review. Merge → auto-deploys.
- Don't commit secrets. `.env*.local` is gitignored. Env vars (`BLOB_READ_WRITE_TOKEN`, `ADMIN_PIN`) live in Vercel, not the repo.
- See `.github/CODEOWNERS` for who reviews what.

## The Out of Pocket (OOP) module

A standalone mini-app inside the Next app. It does **not** depend on the
generic platform code (no imports of `lib/types.ts` or `lib/branding.ts`), so
you can work on it in isolation. All OOP files:

```
web/src/app/out-of-pocket/
  page.tsx          # Lobby: "Edit Trivia" / "Present Game"
  present/page.tsx  # Presenter (slides, fullscreen, session timer)
  edit/page.tsx     # Editor (gated by OopAdminGate)
  deck.ts           # ★ Deck data model + DEFAULT_SECTIONS (baked-in deck) + buildDeck()
  layout.tsx        # Wraps everything in .oop-scope
  oop.css           # Brand tokens (--oop-pink/cyan/yellow/navy) + Baloo Da 2 font
  questions.csv     # Generated by `bun run export-csv` (tracking ledger)
web/src/components/oop/
  OopSlides.tsx         # Slide templates (cover/section/question/reveal) over OOP PNG backgrounds
  OopQuestionEditor.tsx # Per-question editor card (all fields, bullets, image upload, preview)
  OopAdminGate.tsx      # Password front-door for the editor
web/src/lib/oopDeck.ts  # Client helpers: loadDeck/saveDeck/resetDeck/uploadImage/verifyPin + factories
web/src/app/api/
  oop-deck/route.ts   # GET/PUT/DELETE the deck (Blob on Vercel, public/data locally)
  oop-image/route.ts  # POST image upload (Blob / public/oop/uploads locally)
  admin-check/route.ts# POST verify admin PIN (no write)
```

### Two layers: content vs code

1. **Content** (the actual questions/rounds) is edited live at `/out-of-pocket/edit`
   and **saved to Vercel Blob** (`oop-deck.json`) — *not* to git. `deck.ts`'s
   `DEFAULT_SECTIONS` is only the seed/default and the "Reset to original" target.
   So: editing questions in the UI does not change the repo, and editing
   `deck.ts` only affects people who haven't saved their own deck (and "Reset").
2. **Code/features** (new slide types, editor fields, layout) is normal repo work.

### Data model (`deck.ts`)

- `DeckSection { number, title, subtitle?, body?, questions: DeckQuestion[] }` — a round.
- `DeckQuestion { number, text, points, answer, bullets?, revealBullets?, codeBlock?,
  questionImageSrc?/2?, questionCaption?, questionSourceUrl?, revealImageSrc?/2?,
  revealCaption?, revealSourceUrl?, sourceLabel? }`.
- `buildDeck(sections)` flattens rounds into a flat `Slide[]` the presenter walks:
  per phase it emits a section divider → question-only slides → an answers divider →
  (question, reveal) pairs. This is the live pacing (read round, collect, reveal).

### Editor security

- The editor is gated by `OopAdminGate` (front door) **and** every write route checks
  `ADMIN_PIN` via the `x-admin-pin` header. `ADMIN_PIN` is set in Vercel. If unset
  (local dev), access is open. The PIN is shared with the generic platform's
  upload/delete. Verified PIN is cached in `localStorage("trivia-admin-pin")`.

### Conventions / gotchas

- Everything OOP renders inside `.oop-scope` (sets the Baloo Da 2 font + `--oop-*` color vars). Use those vars, not hard-coded hex.
- The presenter sizes the slide card as the largest 16:9 box that fits, via a CSS
  size container (`100cqh × 16/9`); the root is `h-dvh` so the container query resolves. Don't reintroduce fixed pixel chrome offsets.
- Adding a new question field: add it to `DeckQuestion` in `deck.ts`, thread it through
  `buildDeck`, the `Slide` types, `OopSlides` (render), `present/page.tsx` (pass-through),
  and `OopQuestionEditor` (edit). Keep all five in sync.
- `bun run export-csv` reads `deck.ts`'s `sections` (alias of `DEFAULT_SECTIONS`).
